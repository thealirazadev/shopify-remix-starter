## Decisions log

- 2026-07-15 — Admin API access is GraphQL-only in new code; the REST client is not used.
- 2026-07-15 — All UI uses Polaris tokens and components; no custom theme or CSS framework.
- 2026-07-15 — Session storage uses Prisma; SQLite in development, Postgres/MySQL in production via `DATABASE_URL`.
- 2026-07-15 — Billing ships as a config-toggleable scaffold so the starter installs without forcing a charge.
- 2026-07-15 — Dependency versions are pinned exactly and the lockfile is committed with any dependency change.
- 2026-07-17 — `@shopify/eslint-plugin` 48.0.2 only exports flat (`eslint.config.js`) configs, not legacy `.eslintrc` configs, despite `eslint` being pinned to 8.57.1 (which supports both). Switched to `eslint.config.js` rather than downgrading the plugin or upgrading eslint, since both are pinned versions and changing either needs approval. A few of the plugin's default rules were overridden in `eslint.config.js` with inline justification: `react/react-in-jsx-scope` and `react/jsx-uses-react` (project uses the automatic JSX runtime), `@shopify/jsx-no-hardcoded-content` and `@shopify/jsx-no-complex-expressions` (Shopify's internal i18n convention, not part of this starter's scope per `docs/design.md`), `import/extensions` (`.server.ts` is a Remix naming convention, not a real file extension), `@typescript-eslint/naming-convention` (third-party option keys like `unstable_newEmbeddedAuthStrategy` and `v3_singleFetch` cannot be renamed), and `n/no-unsupported-features/node-builtins` (Node 18.20+ ships `fetch`/`Request`/`Response`/`Headers` as stable globals that Remix depends on).
- 2026-07-17 — Billing plan is always declared in the `shopifyApp()` config (not conditionally `undefined`) so the Shopify package's generic types stay concrete; whether the check ever runs is controlled entirely by the `BILLING_ENABLED` env var inside `app/lib/billing.server.ts`. This keeps the "installs without forcing a charge" guarantee without fighting TypeScript's generic inference.
- 2026-07-17 — **Human required:** nothing here has been installed against a real Shopify Partners app or development store — there is no live Partner account/store available in this environment. OAuth, embedded framing, webhook delivery, and billing were verified as far as possible without one: unit tests for pure logic (validation, error shape, webhook topic dispatch), a manual boot check of the built server (root route redirects to `/auth/login` as expected with no `shop` param), and a manual check that a missing required env var throws a readable startup error. Before this starter is used for real: a human with Partner Dashboard access needs to (1) create/point a Shopify app at a dev store, fill in real `.env` values, run `shopify app dev` to get a tunnel URL synced into `shopify.app.toml`, (2) install the app on that store and confirm the OAuth round trip, embedded Polaris/App Bridge framing, and NavMenu navigation, (3) confirm a `Session` row is written (`npx prisma studio`), (4) trigger webhooks (including uninstall and the three compliance topics) via the Shopify CLI and confirm 200s and correct session/data cleanup, and (5) exercise the billing demo route with `BILLING_ENABLED=true` against a test charge.
